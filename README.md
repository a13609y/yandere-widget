# yande.re 动漫图 · Egern 小组件

从 [yande.re](https://yande.re) / [Konachan](https://konachan.net) 按标签取动漫插画，按小组件尺寸匹配画幅。免登录。

## 安装

Egern → 模块 → 右上角 + → 从 URL 导入：

```
https://raw.githubusercontent.com/a13609y/yandere-widget/main/yandere.yaml
```

> 改完参数没生效：删掉模块重新导入（Egern 对脚本有 `update_interval` 缓存）。

## 为什么用这个源

Wallhaven 的缩略图是**固定 432×243 的横向裁切**（竖图也被裁成横的），而原图动辄 2~10MB，iOS 桌面小组件渲染不出来。

yande.re 的 `sample` 图正好：**长边 1500px，体积 200~500KB**，不压缩也够清晰、体积也压得住。

## 参数

| 参数 | 作用 | 默认 |
|---|---|---|
| 标签 | yande.re 只有标签、没有全文搜索；多个标签是「同时满足」，用空格或逗号分隔 | 空（随机） |
| 图源 | 自动 / yande.re / Konachan | 自动 |
| 排序 | 随机（每次抽新的一批）/ 热度（全站评分降序，偏老）/ 最新（发布倒序） | 随机 |
| 时段 | 不限 / 一天内 / 一周内 / 一个月内 / 三个月内 / 半年内 / 一年内 / 两年内 / 三年内（`date:>YYYY-MM-DD`） | 不限 |
| 最低评分 | 0 / 50 / 100 / 200 / 500，低于此分数跳过 | 0 |
| 画幅·小号 / 中号 / 大号 / 超大号 | 方图 / 横图 / 竖图 / 不限 | 方/横/方/横 |
| 分级开关 | 全年龄(s) / 擦边(q) / 工口(e) 三个独立开关，自由组合 | s ✓ q ✓ e ✗ |
| 最小短边 | 短边低于此值跳过 | 1024 |
| 排除·露点 / 胖次 / 内衣 / 透视 / 裸体 / 骆驼趾 | 命中对应标签就跳过（本地过滤） | 全开 |
| 排除·多格/拼图 / 草图页 / 白底 | comic/4koma/collage、sketch_page 等、white_background/transparent_background | 前两项开、白底关 |
| 排除·萝莉正太 / 捆绑 | 同上 | 关 |
| 排除·自定义标签 | 多个用逗号分隔（`guro, vore`）；标签内空格自动转下划线 | 空 |
| 换图间隔 | 分钟 | 30 |
| 防重复窗口 | 全尺寸共用历史 | 100 |
| 显示分辨率 | 左下角 分辨率 + 收藏数 | true |
| 调试角标 | 版本/图源/比例/分级/体积/标签/搜索次数 | false |

画幅判定按图片**实际宽高比**：≥1.35 横图、0.75~1.35 方图（4:3、5:4、4:5 这类近似方也算）、<0.75 竖图。

方图区间放宽到 0.75~1.35 是故意的：小组件是 cover 填充，4:3、5:4、4:5 这类“近似方”裁掉一点边看不出来，但可选素材能多出一大截。

## 标签怎么写

- 单个：`landscape`、`hatsune_miku`、`sky`
- **中文也行**：内置常用别名表，`初音`→`hatsune_miku`、`樱花`→`cherry_blossoms`、`猫耳 泳装`→`cat_ears swimsuit`；表里没有的中文词会被忽略（不会让整条查询变 0 条）
- 多个（同时满足）：`blue_sky clouds`
- 排除：`-rating:e`（分级选项已经在做这件事）

常用标签：`landscape`（风景横图）、`sky`、`clouds`、`hatsune_miku`、`original`、`scenery`。

**注意**：yande.re 的标签库和 Danbooru 不一样，有些标签它根本没有（实测 `sky` 在 yande.re 是 0 条，在 Konachan 有）。所以「图源=自动」时，yande.re 没结果会自动换 Konachan 再试；两个都没有，就退回「只按分级随机」，调试角标会显示 `⚠标签无结果已随机`。

## 排序 × 时段 怎么配合

| 组合 | 实际请求 | 效果 |
|---|---|---|
| 热度 + 一周内 | `order:score rating:x date:>一周前的日期` | 最近的图里评分最高的 |
| 随机 + 一个月内 | `order:random ... date:>…` | 一个月内随机抽 |
| 最新 + 任何时段 | `order:date ...`（时段被忽略） | 最新发布，时段无意义 |
| 热度 + 一天内 | 先按一天内查，没图会自动放宽 | 角标显示 `⚠时段` |
| 任意 + 最低评分 | 分数不够会自动放宽 | 角标显示 `⚠评分` |

yande.re 只支持 `date:>日期` / `date:A..B`，**不支持 `age:<1week`**（实测 0 结果），所以时段是用日期算出来的。

## 为什么要本地排除标签

yande.re 的 `rating:s` **不保证内容真的全年龄**：实测 100 条 `rating:s` 里仍有 `nipples`、`loli`、`panties` 这类标签的作品——本体是投稿者自己标的分级。

而且它的 `-tag` 反选**实测无效**（`hatsune_miku -loli` 和不带 `-loli` 结果完全一样，只对 `rating:` 这种元标签生效），所以这些排除只能抓回来之后在本地按标签精确匹配剔除。

排除是**按 `_` 分段匹配**的：`nipples` 能命中 `erect_nipples`，但 `bra` 不会误伤 `braid`。

开关对应关系：

| 开关 | 排除的标签 |
|---|---|
| 露点 | `nipple` `nipples`（按段匹配，`erect_nipples`、`puffy_nipples` 也一起排） |
| 胖次 | `panties` |
| 内衣 | `underwear` `bra` |
| 透视 | `see_through` |
| 裸体 | `nude` `topless` `completely_nude` |
| 骆驼趾 | `cameltoe` `spread_legs` |
| 萝莉/正太 | `loli` `shota` |
| 捆绑 | `bondage` |

## 已知限制

- **单张 > 1.2MB 会被跳过**（iOS 桌面小组件渲染不出来）。sample 图基本都在 200~500KB，很少触发。
- 「仅擦边 + 窄画幅」组合素材偏少：实测 `rating:q` 每次请求约 20 条，其中横图约 15%（每次约 3 张可用），偶尔会出现一轮拿不到图 → 显示错误卡片，15 分钟后自动重试（有缓存时会继续显示旧图）。
- yande.re 的接口没有画幅参数，画幅是在本地按宽高比筛的，所以一页 30 条里可能只有一部分符合。
- `order:random` 必须放在标签串最前面，脚本已经处理；这也是「不填标签就是随机」的实现方式。
