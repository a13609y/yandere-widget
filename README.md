# yande.re 动漫图 · Egern 小组件

从 [yande.re](https://yande.re) / [Konachan](https://konachan.net) 按标签取动漫插画，按小组件尺寸匹配画幅。免登录。

## 安装

Egern → 模块 → 右上角 + → 从 URL 导入：

```
https://raw.githubusercontent.com/a13609y/yandere-widget/main/yandere.yaml
```

> 改完参数没生效：删掉模块重新导入（Egern 对脚本有 `update_interval` 缓存）。

## 为什么用这个源

Wallhaven 的缩略图是**固定 432×243 的横向裁切**（竖图也被裁成横的），而原图动辄 2~10MB，iOS 桌面小组件渲染不出来。

yande.re 的 `sample` 图正好：**长边 1500px，体积 200~500KB**，不压缩也够清晰、体积也压得住。

## 参数

| 参数 | 作用 | 默认 |
|---|---|---|
| 标签 | yande.re 只有标签、没有全文搜索；多个标签是「同时满足」，用空格或逗号分隔 | 空（随机） |
| 图源 | 自动（**先 Konachan**，空了再 yande.re）/ yande.re / Konachan | 自动 |
| 排序 | 随机（每次抽新的一批）/ 热度（全站评分降序，偏老）/ 最新（发布倒序） | 随机 |
| 时段 | 不限 / 一天内 / 一周内 / 一个月内 / 三个月内 / 半年内 / 一年内 / 两年内 / 三年内（`date:>YYYY-MM-DD`） | 不限 |
| 最低评分 | 0 / 50 / 100 / 150 / 200，低于此分数跳过（**服务端就筛**，随机抽样也只在高分池里抽）；上限锁 200，理由见下 | 0 |
| 画幅·小号 / 中号 / 大号 / 超大号 | 方图 / 横图 / 竖图 / 不限 | 方/横/方/横 |
| 画幅·自定义容忍 / 容忍百分比 | 开关 + 百分比（默认 10） | 关 / 10 |
| 分级开关 | 全年龄(s) / 擦边(q) / 工口(e) 三个独立开关，自由组合 | s ✓ q ✓ e ✗ |
| 最小短边 | 短边低于此值的 60% 才跳过（默认 1024 → 实际 614） | 1024 |
| 排除·露点 / 胖次 / 内衣 / 透视 / 裸体 / 骆驼趾 | 命中对应标签就跳过（本地按 `_` 分段匹配） | 前六项全开 |

| 排除·白色（white） | 只匹配整词 `white`，不误伤 `white_hair` ｜ 站点：仅 Konachan | 关 |
| 排除·萝莉正太 / 捆绑 | 同上 | 关 |
| 排除·自定义标签 | 多个用逗号分隔（`guro, vore`）；标签内空格自动转下划线 | 空 |
| 换图间隔 | 分钟；**0 = 每次刷新都实时请求新图**（测试用，不走候选池） | 30 |
| 防重复窗口 | 全尺寸共用历史 | 100 |
| 显示分辨率 | 左下角 分辨率 + 收藏数 | true |
| 调试角标 | 版本/图源/比例/分级/体积/标签/搜索次数 | false |

画幅判定有两种方式：

**默认（粗分档）**：≥1.35 横图、0.75~1.35 方图（4:3、5:4、4:5 这类近似方也算）、<0.75 竖图。

方图区间放宽到 0.75~1.35 是故意的：小组件是 cover 填充，4:3、5:4、4:5 这类“近似方”裁掉一点边看不出来，但可选素材能多出一大截。

**可选（自定义容忍）**：打开「画幅 · 自定义容忍」后，改成按**理想比例 ±N%** 收图：

| 画幅 | 理想比例 | 10% 时接受区间 |
|---|---|---|
| 横图 | 1.78 | 1.60 ~ 1.96 |
| 方图 | **1.33**（4:3） | 1.20 ~ 1.46 |
| 竖图 | 0.71 | 0.64 ~ 0.78 |

N 由「画幅 · 容忍百分比」控制（5~50，留空按 10）。画幅选「不限」时这个开关不生效。

**注意**：booru 站的「方图」大多是 **4:3（1.33）**，不是严格 1:1。所以自定义容忍的基准也按 1.33 算（v5.4 起）：10% 时方图收 1.20~1.46，能正常取到图（这批图 100% 覆盖）；以前按 1.00 算（0.85~1.15）时几乎一张都命中不了，才会出现“一开容忍就刷不出来”。

想真的只要 1:1，把容忍调小到 5~8 左右即可（1.33 ±8% ≈ 1.22~1.44，其中仍有 4:3 的图）；要严格 1:1 目前做不到，因为源站几乎没有 1:1 的正片。

## 不再缓存候选图（v5.1）

池子彻底去掉了，**每次刷新都实时请求**（1 个 API 请求 + 1 张图）。留下来的只有 `plan`（上次生效的档位）和翻页游标 —— 那是为了不让放宽链每次都重走一遍，不是图片缓存。

原因：攒一批图再慢慢放，第一张要等整批才出来，而且对图床是“突然一串请求”，容易被当成爬虫限流。现在一次一张，节奏跟人手动换图差不多。

「显示 · 换图间隔」默认改成 **0**（每次刷新都换）；设成 >0 才是“间隔内直接显示上次那张、不联网”。

## 库尽时怎么处理（v5.0）

判断标准从「查询有没有返回图」改成「有没有**没看过**的图」：

- 某一档返回了 100 张，但全在防重复窗口里 → 视为**库尽**，继续往下放宽（200 → 150 → 100 → 50 → 放时段）；
- 一直放宽到底还是没有新图，才会从看过的图里轮换一张，并在调试行标 `库尽轮换`；
- 放宽命中的那张图会带着 `⚠评分187<200` 之类的角标，不会假装没放宽。

所以现在不会出现「明明库尽了一直给你看旧图、也不会降评分」这种情况了。

## 最低评分为什么是 200 封顶

分数是**累计值**（收藏 − 反对），越老的图越高。所以「高评分」实际等价于「只收老图」，和短时段天然打架；而候选集一旦比池子（80）和防重复窗口（100）还小，就只会原地轮换。

实测 Konachan「三年内」各档的图量（擦边+全年龄）：

| 最低评分 | 每批返回 | 全站规模 |
|---|---|---|
| 150 | 100 张 | 274+ 张 |
| 200 | 100 张 | 约 200 张 |
| 300 | 只有 49 张 | 全站就 49 张（无意义） |
| 500 | 只有 3 张 | 全站 3 张（无意义） |

所以选项只保留到 200；旧配置里存的 300/500 会被自动按 200 处理，不会再出现「一直是那几张图」。

推荐配方：**一周内 50、一个月内 100、一年内 100~150、三年内或不限 150~200**。只勾「全年龄」时（走 `.net`）一年内最高约 190 分，一年内别再往上调。

## 最低评分为什么「看起来没生效」

v4.5 及以前的评分是**本地筛**：先随机抽 100 张，再把低于阈值的剔掉。问题是时段越短、分数上限越低，随机抽的那批里根本没几张高分图，于是每次都筛空 → 触发「去掉评分」兜底 → 显示一堆 ♥20 的图，而放宽角标只在 DEBUG 里露出，看不出发生了什么。

实测（2026-11，Konachan）：

| 查询 | 返回 | 分数区间 |
|---|---|---|
| 随机 + 一年内（不限分） | 100 张 | 最高 151~181（三批都 0 张 ≥200） |
| 热度 + 一年内（前 100） | 100 张 | 最高 **190** |
| 随机 + 一年内 + `score:>199` | **0 张** | — |
| 随机 + 三年内 + `score:>199` | 29 张 | 203~617 |
| 不限时段 + `score:>199` | 100 张 | 201~808 |

结论：**「一年内 + 200 分」本身就是一个空集合**，不是筛选坏了。

v4.6 起改成：

1. 评分交给服务端（`score:>N-1`），随机抽样直接发生在高分池里，不再「抽完再扔」；
2. 真取不到时按 **200 → 150 → 100 → 50** 逐级降档，而不是一步砍到 0；
3. 降档信息写进调试行（打开「调试角标」才显示 `⚠评分51<200`），封面保持干净；
4. 时段兜底也改成阶梯（一天→三天→一周→…），不会再一下子跳到二零一几年的老图。

想守住高评分：把时段放宽到「三年内」或「不限」；想守新鲜度：评分选 100 比较稳。

## v4.7 修的几处坑

- **池子按「当前档位」分桶**：严格档位和放宽档位的图分开存，档位一换整批作废。这样放宽档位拿到的图也能复用（不然每次刷新都要重走整条放宽链，出现「3 搜 + 老是那几张」）。
- **放宽档位会被记住**：第一次摸到「50 分才够」之后，`pool.plan` 记下这个档位，并把这一档的图一起入池 —— 下次刷新 0 个请求、直接换图（实测 12 秒 → 0.9 秒）。
- **角标按「这张图自己的档位」算**，存进池子也带着 —— 之前从池子里取图时会丢掉 `⚠时段/⚠标签`。
- **同一张图不会连着出现**：可用素材被防重复窗口用尽时，会轮换一张别的，而不是原样重放上一张。
- **下不下来的图记 7 天**（`yd_bad`），限流属于暂时失败，只在本轮跳过，不写进去。
- **yande.re 的 `order:random` 叠 `date:` 几乎必空**，所以 yande 走随机时直接跳到「时段不限」，不再白试几个中间档。
- **锁屏组件**会去找任意尺寸的缓存（以前只认小/中号）。

## 标签怎么写

- 单个：`landscape`、`hatsune_miku`、`sky`
- **中文也行**：内置常用别名表，`初音`→`hatsune_miku`、`樱花`→`cherry_blossoms`、`猫耳 泳装`→`cat_ears swimsuit`；表里没有的中文词会被忽略（不会让整条查询变 0 条）
- 多个（同时满足）：`blue_sky clouds`
- 排除：`-rating:e`（分级选项已经在做这件事）

常用标签：`landscape`（风景横图）、`sky`、`clouds`、`hatsune_miku`、`original`、`scenery`。

**注意**：yande.re 的标签库和 Danbooru 不一样，有些标签它根本没有（实测 `sky` 在 yande.re 是 0 条，在 Konachan 有）。所以「图源=自动」时，yande.re 没结果会自动换 Konachan 再试；两个都没有，就退回「只按分级随机」，调试角标会显示 `⚠标签无结果已随机`。

## 排序 × 时段 怎么配合

| 组合 | 实际请求 | 效果 |
|---|---|---|
| 热度 + 一周内 | `order:score rating:x date:>一周前的日期` | 最近的图里评分最高的 |
| 随机 + 一个月内 | `order:random ... date:>…` | 一个月内随机抽 |
| 最新 + 任何时段 | `order:date ...`（时段被忽略） | 最新发布，时段无意义 |
| 热度 + 一天内 | 先按一天内查，没图会自动放宽 | 角标显示 `⚠时段` |
| 任意 + 最低评分 | 先带上 `score:>N-1` 查询；还是空就按 200→150→100→50 逐级降档，再不行才放宽时段 | 调试行显示 `⚠评分51<200` / `⚠时段` |

yande.re 只支持 `date:>日期` / `date:A..B`，**不支持 `age:<1week`**（实测 0 结果），所以时段是用日期算出来的。

## 为什么要本地排除标签

yande.re 的 `rating:s` **不保证内容真的全年龄**：实测 100 条 `rating:s` 里仍有 `nipples`、`loli`、`panties` 这类标签的作品——本体是投稿者自己标的分级。

而且它的 `-tag` 反选**实测无效**（`hatsune_miku -loli` 和不带 `-loli` 结果完全一样，只对 `rating:` 这种元标签生效），所以这些排除只能抓回来之后在本地按标签精确匹配剔除。

排除是**按 `_` 分段匹配**的：`nipples` 能命中 `erect_nipples`，但 `bra` 不会误伤 `braid`。

开关对应关系：

| 开关 | 排除的标签 |
|---|---|
| 露点 | `nipple` `nipples`（按段匹配，`erect_nipples`、`puffy_nipples` 也一起排） |
| 胖次 | `panties` |
| 内衣 | `underwear` `bra` |
| 透视 | `see_through` |
| 裸体 | `nude` `topless` `completely_nude` |
| 骆驼趾 | `cameltoe` `spread_legs` |
| 萝莉/正太 | `loli` `shota` |
| 捆绑 | `bondage` |

## 已知限制

- **单张 > 1.2MB 会被跳过**（iOS 桌面小组件渲染不出来）。sample 图基本都在 200~500KB，很少触发。
- 「仅擦边 + 窄画幅」组合素材偏少：实测 `rating:q` 每次请求约 20 条，其中横图约 15%（每次约 3 张可用），偶尔会出现一轮拿不到图 → 显示错误卡片，15 分钟后自动重试（有缓存时会继续显示旧图）。
- yande.re 的接口没有画幅参数，画幅是在本地按宽高比筛的，所以一页 30 条里可能只有一部分符合。
- `order:random` 必须放在标签串最前面，脚本已经处理；这也是「不填标签就是随机」的实现方式。
